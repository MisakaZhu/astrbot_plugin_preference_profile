## 1. 目标与非目标

目标：让「关闭/删除」只使**本插件创建的那一份**临时内容失效——在
组装后仍能从已登记的源对象找到它对应的**实际运行时对象**，并按对象
身份置空；他人同文/同 temp/带前后文的派生副本不继承该关联。

非目标：不改产品合同（V11 语义不变）；不改变 `Message`/Provider
序列化行为；不把归属映射写入聊天历史或 Provider 参数；不解决"已真正
发出的请求不可撤回"（既有边界，如实保留）。

## 2. 推荐方案：宿主在实际转换处记录 源对象 → 实际运行时对象 配对

**建立时点**：宿主在组装当前轮次 user 消息的最终一步——即
`ProviderRequest.assemble_context()` 产出字典、经
`Message.model_validate` 得到**最终运行时实例**之后——记录
`源 ContentPart（req.extra_user_content_parts 中的对象） →
Message.content 中的实际对象`。只保存跨过 `model_validate` 的最终
实例；序列化前的字典或理论索引不够（第九轮已证原生路径在该步丢失
对象身份与私有属性）。

**请求/轮次范围与生命周期**：映射为纯内存结构，按当前轮次组织
（挂在 run_context/轮次上下文，而非全局）；对源对象与运行时对象均持
弱引用，不延长宿主对象生命周期；轮次终态（正常完成、ERROR、
stop_event 中止、asyncio 取消、`turn_off_plugin`/terminate）与
TurnRegistry 同步清理，不晚于现有 registry 释放时点。

**晚复制为什么不继承**：映射的值只指向「由该源对象经宿主转换产生的
那一个运行时实例」。他人插件以相同 text 新建 part、`model_copy`/
deepcopy 或整字典重建产生的**新源对象**不经本插件的源转换路径，不在
映射中；reset 之后运行时层再复制同样产生映射外的新对象。**别名引用
同一对象不属于新副本**（契约需明确写出）。元数据、正文与 `_no_save`
完全相同都不改变上述规则——判据是转换来源，不是内容相等。

**失效信号两段式**：关闭/删除可发生在组装前、组装等待中（历史压缩
await、-2000 合法钩子）、reset 后、工具中间回复后。关联未建立时沿用
现状（req 侧按 TurnRecord.parts 对象身份移除，dead 标记保留）；关联
建立后按映射对运行时实例补偿置空。推式失效（PrefStore/配置写回调）
接入同一补偿点。

**多步 Agent**：第二次模型调用前若宿主重建消息对象或另建发送快照，
必须更新映射或提供明确失效通道；不得把第一次调用完成当作后续请求已
发送（既有 T6a 语义保持：中间回复装饰不等于轮次终态）。

**异常与边界**：模态过滤会用 `replace(request)` 复制请求——设计须
定义原请求与调整后请求共享同一轮次映射；图片/音频处理的 await 边界、
组装失败时映射状态为「未建立」，不产生半关联。默认关闭、未启用、非
LLM 轮次不注入也不建立映射，零干预；普通用户文本、其他插件块与原生
text 注册表不受影响。

**双版本**：4.26 与 4.28 的 runner 组装路径需逐版核验（含 `_assemble_
request_context_for_provider` 的模态分支差异）；无法同时兼容时给最低
宿主版本与迁移说明。

## 3. 元数据字段（owner_key）方案为何不等于「加字段即可」

全对象复制（`model_copy`/deepcopy）与整字典重建都会携带新字段；
未定义「新建/复制/重建」语义的普通字段无法证明复制不继承。若采用
字段路线，必须由宿主提供受控的新建/复制语义，并证明他人把字段值
伪装成相同值也不会使清理扩散到他人对象——否则退回当前内容令牌的
同一问题。因此它只是备选，不是推荐解。

## 4. 离线最小验证（本轮已完成，未修改宿主）

已验证（双版本，conversion_chain_probe 与 x_rework·X5，冻结于
独立复核第九轮）：

1. 原生 extra parts 路径丢失源对象身份与自定义私有属性；
2. TextPart 模型字段仅 type/text，`_no_save` 为宿主特判；
3. 同文 temp 副本与本尊在 `(type, text, _no_save)` 上不可区分。

本轮补充验证（`instance_retention_probe`，宿主源码事实，双版本）：

4. `ContentPart` 校验器对**已传入的 ContentPart 实例**直接保留同一
   实例（`astrbot/core/agent/message.py` validator 的
   `issubclass(value.__class__, cls)` 分支）——宿主存在「保留实例」
   的既有通道；但默认 extra parts 路径先转字典、不经过该分支。此
   事实说明映射方案的落点（让配对在组装处建立并返回最终实例）与宿主
   现有结构兼容，**不等于**现有插件已有可靠通道，也不构成实现。

未验证：完整映射实现、双版本组装路径差异的实测覆盖、性能影响——
留待宿主侧独立源码副本的最小设计验证（与 Codex 草案一致）。
